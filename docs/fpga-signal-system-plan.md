# FPGA 信号发生与采集系统 — 开发计划文档

> 日期：2026-07-09
> 配套需求文档：`2026-07-09-fpga-signal-system-design.md`
> 面向 vibe coding 逐步推进：每个阶段有明确交付物 + 验证方法 + 完成标准。

---

## 总体策略

**先易后难、先单链路后打通、每步可验证。**

开发顺序原则：

1. **先做 DAC 信号发生**——有商家例程波形可参考，示波器直接看输出即可验证，不依赖 PC。
2. **再做 AD9226 采集**——用 ILA 抓码值验证，独立于 DAC。
3. **再打通 UART 双向协议**——连接 FPGA 与上位机。
4. **最后做上位机软件**——通信→显示→控制→存储逐层加。
5. **可选第二阶段**——130Msps 交织、连续采集、性能优化。

每个里程碑结束都能"看到东西动"，避免一次性写完再调试的黑箱风险。

## M0 — 工程骨架与时钟、串口回环

**目标**：搭好 Vivado 工程基础设施，验证时钟和串口能工作。

**任务**
1. 确认 `Signal.xpr` 器件 xc7a35tfgg484-2L；建立 `rtl/`、`ip/`、`constraints/`、`sim/` 目录结构。
2. 用 **Clocking Wizard** 生成 MMCM：输入 50MHz → 输出系统时钟、ADC 采样时钟（65MHz）、ADC 读时钟（65MHz +4ns 相位）、SPI 时钟。
3. 写 `uart_rx.v` / `uart_tx.v`（波特率参数化，先 115200 便于调试）。
4. 顶层做**串口回环**：RX 收到的字节直接 TX 发回。
5. 编写初版 XDC（时钟、复位、UART TX/RX 引脚）。UART/时钟/复位引脚见需求文档附录 D.3（板载信号，须先查 ATK_DFM484Z 官方引脚表填入 TBD）。

**验证**：串口调试助手发字符，能原样收回。ILA 观察 MMCM 各时钟锁定。

**完成标准**：串口回环通过，时钟 locked。

---

## M1 — DAC8830 信号发生（本地固定参数）

**目标**：FPGA 独立驱动 DAC8830 输出三种波形，示波器可见。

**任务**
1. 生成正弦 **`.coe`** 表（4096×16bit），用 **Block Memory Generator** 例化 `wave_lut` ROM。
2. 写 `dds_phase.v`：32bit 相位累加器，FTW 先用固定值（如 1kHz）。
3. 写波形选择：正弦（查表）、三角（相位高位线性）、方波（相位 MSB）。
4. 写 `amp_scale.v`：幅度缩放到 16bit DAC 码（先固定满幅）。
5. 写 `dac8830_spi.v`：双片选状态机，CS 低有效、bit15→bit0、SCLK 上升沿采样/MOSI 下降沿变化、CS 高保持≥30ns。参考 DAC8830 指南第 5 节，但用 Xilinx 时序重写。
6. 顶层用常量参数驱动，通道 1/2 各输出一种波形。

**验证**：示波器接 DAC A0/B0，看到正弦/三角/方波，频率约 1kHz。切换波形（先用拨码或常量重编译）确认三种都对。

**完成标准**：三种波形正确输出，频率符合 DDS 计算值。

**关键点**：确认 DAC8830 跳帽=双极性 ±5V；MOSI/SCLK 相位正确（波形无毛刺）。

---

## M2 — AD9226 采集与 ILA 验证

**目标**：FPGA 正确采集 AD9226 双通道 12bit 码值。

**任务**
1. 写 `ad9226_capture.v`：用 ADC 读时钟（+4ns）锁存 `Adc_In_A/B`，做 `raw ^ 0xFFF` 得 code，输出 over_range 标志。参考 ad9226 指南第 6、13 节，用 Xilinx 重写。
2. 顶层输出 `Adc_Clk_A/B`（65MHz），从模块读入 12bit 数据。
3. 编写 AD9226 相关 XDC（数据总线、时钟、Otr）。
4. 插入 **ILA** 抓 code_a/code_b。
5. 给 INA/INB 输入已知信号（如信号发生器 1kHz 正弦或 M1 的 DAC 输出）。

**验证**：ILA 看到的 code 波形与输入信号一致；边界符合 `raw 0xFFF→code 0x000→−5V`、`raw 0x000→code 0xFFF→+5V`。用 DAC 输出接 ADC 输入形成自测环。

**完成标准**：ILA 抓到正确正弦码值，无位序错误、无明显跳变。

**风险**：读时钟相位需按实际布线微调；位序（A1=bit0）不可颠倒。

## M3 — UART 命令协议与参数下发

**目标**：上位机（或串口助手）通过命令帧改发生/采集参数。

**任务**
1. 写 `cmd_parser.v`：解析 `0xAA 0x55 | CMD | LEN | PAYLOAD | CRC`，校验 CRC，分发到 `reg_file`。
2. 写 `reg_file.v`：参数寄存器（波形、FTW/频率、幅度、通道、触发阈值、边沿、采集深度…）。
3. 把 M1 的 DDS/波形/幅度改为读 `reg_file`（不再是常量）。
4. 定义命令集与编码（写进本文档附录，供上位机对齐）。
5. 加状态查询命令（返回版本/状态帧）。

**验证**：串口调试助手发命令帧，改变频率/波形/幅度，示波器看到 DAC 输出实时变化。

**完成标准**：至少能远程改发生参数并即时生效；CRC 错误帧被正确丢弃。

---

## M4 — 边沿触发、BRAM 帧缓冲与回传

**目标**：命中触发采一帧存 BRAM，经 UART 回传。

**任务**
1. 写 `trigger.v`：阈值比较 + 上升/下降沿检测 + 预触发计数（触发点居中）。
2. 写 `frame_buffer.v`：BRAM 环形缓冲，持续写；触发后再写 N/2 点停止；记录起止指针。
3. 写 `readout_fifo.v`：采样域 → 系统域 XPM FIFO；把 12bit 码打包成字节流。
4. 写数据帧打包：`0xA5 0x5A | TYPE | FRAME_LEN | CH | SAMPLES | CRC`，经 uart_tx 分块发出。
5. 命令集加：设触发参数、启动单次采集、连续采集开关。

**验证**：写一个临时 Python 脚本，发采集命令，收一帧，解包后用 matplotlib 画出——应看到稳定不漂移的触发波形。

**完成标准**：单次采集帧完整、CRC 正确、触发点居中、波形与输入一致。

**关键点**：BRAM 深度上限计算（约 7 万点/通道）；跨时钟域 FIFO 不溢出。

---

## M5 — 上位机软件

**目标**：完整 PyQt 上位机，实现通信+显示+控制+存储。

**任务（分层，逐层验证）**
1. `comm/protocol.py`：命令帧/数据帧编解码（与 M3/M4 对齐）。
2. `comm/serial_link.py`：pyserial 收发线程、帧同步/重组、信号槽通知 UI。
3. `ui/main_window.py` + `ui/plot_widget.py`：界面布局 + pyqtgraph 双通道波形。
4. `core/waveform.py`：code→电压换算（`code/4095·10000−5000`）、频率（FFT/过零）、峰峰值测量。
5. 参数控制面板：发生（通道/波形/频率/幅度）+ 采集（通道/采样率/触发阈值/边沿/深度）→ 下发命令。
6. `db/mysql_store.py`：PyMySQL 建表、存采集记录与参数、查询回放。
7. 连接状态区：串口选择/波特率/连接按钮。

**验证**：连接 FPGA，设参数→DAC 输出变化；触发采集→波形显示；测量读数正确；数据存入 MySQL 并可查询。

**完成标准**：界面简练美观，四大功能（通信/显示/控制/存储）全部闭环可用。

---

## M6 — 系统联调与指标验收校准

**目标**：逐条对照指标表验收，做误差校准。

**任务**
1. 用外部万用表/示波器标定 DAC 输出幅度，校准幅度码映射（达 ±3%）。
2. 用频率计/示波器验证输出频率精度（达 ±1%）。
3. 用已知标准信号验证采集电压/频率测量误差（±3%/±1%）。
4. 验证双通道 50Msps、单双通道带宽指标。
5. 填写"指标→实测"对照表，记录偏差与校准系数。

**完成标准**：需求文档第 5 节指标表全部达标（第一阶段范围内）。

---

## M7（可选，第二阶段）— 130Msps 交织与优化

**目标**：实现单通道 100/130Msps，补齐单通道 4MHz/100Msps 指标。

**任务**
1. 实现交织采样：A 用正相 65MHz、B 用反相 65MHz ADC 时钟（ad9226 指南第 7 节）。
2. 用 XPM mixed-width FIFO（24bit 写 / 12bit 读）合并为 130Msps 单路流。
3. 校准 A/B 输出顺序与相位（用 ILA 检查合并后波形无跳变）。
4. 可选：连续采集/滚动显示、更高波特率、上位机 FFT 频谱显示。

**完成标准**：单通道 130Msps 采集正确，合并波形平滑。

## 附录 B：命令/数据帧格式（M3/M4 细化，两端共用）

**命令帧（PC→FPGA）**：`0xAA 0x55 | CMD(1) | LEN(1) | PAYLOAD(LEN) | CRC(1)`

| CMD | 含义 | PAYLOAD |
|---|---|---|
| 0x01 | 设发生参数 | 通道, 波形, 频率字(FTW), 幅度码 |
| 0x02 | 设触发/采集参数 | 通道, 阈值, 边沿, 深度N |
| 0x03 | 启动单次采集 | — |
| 0x04 | 连续采集开关 | 0/1 |
| 0x05 | 查询状态 | — |

**数据帧（FPGA→PC）**：`0xA5 0x5A | TYPE(1) | FRAME_LEN(2) | CH(1) | SAMPLES(12bit打包) | CRC(1)`

> 具体字段宽度/字节序在 M3 实现时确定并回填此附录，作为 FPGA 与上位机的唯一协议契约。
